/다시 찾는 저장, 해결 아이디어 50

릴스를 즐기는 흐름을 끊지 않으면서 저장을 적재적소에 쉽게 하고, 큰 노력 없이 다시 찾게 한다.

인터뷰 8명에서 나온 것과 다른 저장 플랫폼 스물다섯 곳을 읽고, 인스타그램 저장됨에 옮겨 올 방법을 쉰 가지로 정리했다. 처음 10가지에 같은 층위로 40가지를 더했다(저장 11, 탐색 15, 관리 14). 아이디어마다 릴스에서 어떻게 저장하는지, 저장함에서 어떤 모습이라 찾기 쉬운지를 세 화면으로 그렸다.

아이디어 50가지, 저장부터 다시 찾기까지

모든 흐름은 릴스에서 시작한다. 1번 화면은 저장하는 순간, 2번과 3번 화면은 저장 직후와 저장함에서 찾는 모습이다. 휴대폰 화면은 흐름을 보여 주는 스케치이고, 실제 인스타그램 화면과 다르다. 아래 버튼으로 단계별로 거를 수 있다(표도 함께 걸러진다).

05

먼저 시험할 조합과 다음 검증

한 아이디어로는 세 단계를 다 풀지 못한다. 사용자 유형마다 조합을 하나씩 두고, 같은 찾기 과제로 비교한다(에이전트 제안).

조합 1, 전체에 두는 사람(B)

01 지금 저장, 나중에 정리 + 04 곧 볼 것 + 06 저장 무렵으로 찾기

흐름은 그대로 두고, 값은 "곧 볼 것" 하나만, 찾을 때는 시점 단서. 근거가 가장 많은 쪽.

조합 2, 많이 쌓인 사람(A)

09 큰 컬렉션 안의 섹션 + 07 장면 미리보기 + 08 글로 찾기

400~580개가 쌓인 컬렉션 안에서 좁히고, 기억하는 장면과 글로 찾는다.

조합 3, 저장함 밖에 두는 사람(C)

02 보고 고르는 저장 시트 + 01의 "전체에 저장됨" 알림

저장을 덜 무겁게 보이게 하고 구조를 알려 준다. 근거가 약해 가장 나중.

비교안으로 둘 것

03 끌어서 바로 넣기, 05 하트와 고정

03은 반대 근거(주연), 05는 "값을 매기면 다시 찾는다"는 근거가 아직 없다. 조합과 나란히 시험해 차이를 본다.

다음 검증, 시킨 행동 대신 이미 한 행동으로

1. 기준선: 본인 저장함에서 "최근에 필요해서 찾았던 걸 다시 찾아 주세요". 걸린 시간, 내린 횟수, 무엇을 보고 골랐는지, 못 찾으면 어디로 갔는지.

2. 비교: 같은 가짜 저장함(예: 저장물 200개, 컬렉션 6개)에서 같은 찾기 과제를 지금 화면과 조합 화면으로. 조건이 같아 전후를 비교할 수 있다.

3. 관리 가설: 일주일 동안 나에게 보내기, 캡처를 할 때 이유를 한 줄씩 남긴다. "곧 볼 것"이 몇 번인지 센다.

    345명, 85,000건메일을 폴더로 정리한 사람이 더 잘 찾지는 않았다(09)

    Think, 40편을 우리 프로젝트에 적용하면

    1. 다시 찾기는 일상이고, 실패는 기억의 공백에서 온다. 재방문은 흔하고(02), 다시 찾기 실패는 기억의 실패다(04, 13). "왜 저장했는지"는 묻지 않기로 했으니, 저장 순간의 시점, 장면, 출처를 자동으로 남겨 단서로 쓴다(아이디어 06, 07, 26, 28).
    2. 정리를 강요하는 건 답이 아니다. 정리해도 더 빨리 찾지 않고(09), 사람은 분류 체계를 정하기 어려워 더미를 쓴다(06, 07). 저장할 때는 더미(전체)를 허락하고, 정리는 나중에 여러 개를 한꺼번에(01, 43).
    3. 그렇다고 검색만으로도 안 된다. 사람은 둘러보기를 56~68%, 검색을 4~15%만 쓰고(10), 알고 찾아도 작은 단서로 좁혀 간다(03). 시점, 계정, 쓰임새로 한 단계씩 좁히는 둘러보기 구조를 먼저, 검색은 보조로(06, 26, 27, 08).
    4. 축은 주제가 아니라 쓰임새와 실행 가능성이다. 사람은 쓰임새로 분류하고(08), 정보를 일시적, 작업 중, 보관으로 다룬다(05). PARA(25)처럼 곧 볼 것(04), 날짜가 있는 목적 컬렉션(46), 보관함(42)으로 나누면 맞는다.
    5. 다시 보기는 저장 직후 한 달에 몰린다. 읽기의 80%가 35일 안(12). 곧 볼 것은 그 안에 비워지는 칸으로, 그 뒤는 보관과 가끔 다시 띄우기로(38, 42). 지우지 못하는 축적(11)은 지우지 않고 치우게 한다.
    6. 고르는 화면은 줄이고, 알아보게 한다. 최근 보드 하나와 추천 둘로 이탈과 시간이 줄었다(16). 재인(19), 순서가 고정된 짧은 목록(20), 배경을 덜 가리는 시트(22)가 같은 방향이다(아이디어 02, 05, 13). 선택 과부하 연구(21)는 반론이 있어 근거로 쓰지 않는다.
    7. 회사 쪽 명분은 보내기에 있다. 사용자는 저장 대신 나에게 보내기로 옮겨 갔고, 회사도 보내기를 핵심 신호로 본다(01, 15). 보내기 시트 안에 저장 칸을 두는 안(16)이 둘을 함께 만족시킨다.

    국내 자료로 다시 확인한 것

    1. 국내에서도 위치로 찾고, 나에게 보낸다. 대학생 593명이 다시 찾을 때 위치 기억 41.7%, 검색 24.8%. 정보를 남기는 방법으로 자신에게 이메일 17.0%(31).
    2. 소통 도구가 저장소가 되면 분류하지 않는다. 메일을 파일 저장에 쓰는 대학생 71.6%, 폴더를 안 쓰는 사람 81.1%, 찾을 때 키워드 검색 84.2%(32). DM 나에게 보내기도 같은 길이다.
    3. 구조는 얕게. 폴더 깊이 2단계가 52.6%(33). 섹션은 한 층까지만(09).
    4. 인스타그램은 틈새 시간에 보고 DM으로 보낸다. 시청 후 DM 공유 25.3%로 세 플랫폼 중 가장 높고, 기다리는 시간에 본다 29.7%(34). 저장은 한 번에, 보내기 흐름 안에.
    5. 보이지 않으면 조절하지 못한다. 데이터가 안 보여 저장을 자각하지 못했다(36). 쌓인 양을 보여 주고 보관을 제안한다(42, 48).
    6. 국내 디자인 연구도 출처, 장소, 맥락으로 간다. 앨범 앱 연구의 개선안(37)이 아이디어 06, 22, 28과 겹친다. 진입은 깊이를 줄이고 아이콘에 글자를(38).

    정량 공백을 채우는 순서(제안)

    1. 성공 기준을 HEART로 정한다(29). 과업 성공 = 찾기 성공률과 시간, 헤맴 점수(28). 채택 = 곧 볼 것 사용률. 재방문 = 저장함 다시 연 횟수. 참여 = 나에게 보내기 대비 저장 비율.
    2. 트리 테스트로 구조를 잰다(27). 쓰임새 거르기, 섹션 이름이 통하는지 약 50명에게 화면 없이 묻는다.
    3. 카노 설문으로 아이디어 50의 우선순위를 정한다(30). 당연, 일차원, 매력으로 나눠 먼저 만들 것을 고른다.
    4. 일주일 일기 연구로 관리 가설을 본다(26). 저장, 나에게 보내기, 캡처를 할 때마다 이유 한 줄.
    5. 기회 해법 나무로 묶는다(24). 결과(다시 찾기 쉬움), 기회(인사이트 8), 해법(아이디어 50), 실험(위 1~4)을 한 장에.
