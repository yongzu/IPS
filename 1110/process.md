# 진행안 — 디스코드 인터페이스디자인 방법을 Saved에 적용

2026-11-10. 에이전트 제안을 사용자가 저장 · 수정 지시. 카드 소팅을 인스타그램 정보구조로 돌리고 진입 문제를 세 번째 축으로 넣은 것은 사용자 결정이다. 단계별 세부(카드 목록 · 태스크 문장 · 인원)는 확정 전.

출발점: 사용자의 2024-2 인터페이스디자인 과제(디스코드 UX 분석). 그 흐름은
휴리스틱 평가(장단점) → 카드 소팅(클로즈드, 분류 기준이 직관적인지) → 유저 테스트(태스크별 0~10점, 막힌 지점) → 최종 인사이트 → 해결 방향(카테고리 재구성 + 인터페이스 재구성) → 기존 I.A. · 개선 I.A. → 시각화.

지금까지의 IPS는 인터뷰로 **왜** 그런지를 확인했다. 디스코드 방법은 **얼마나 · 어디서** 막히는지를 재고 해결안을 만든다. 둘을 이어 문제 확인부터 해결안까지 한 흐름으로 간다.

## 세 축

```
저장할 때 (H1 분류 비용) → 저장함까지 갈 때 (진입 비용) → 저장함 안에서 (H2 찾는 비용)
```

- H1 저장 쪽: 맞는 컬렉션이 없을 때 새로 만드는 일이 번거로워 전체 저장이나 애매한 컬렉션에 넣는다. → 저장 시 폴더 생성 · 추천 제안
- 진입: 저장함이 프로필 → 메뉴 안 깊은 곳에 있어 다시 열기까지 여러 단계를 거친다. → 저장함을 꺼내는 I.A. 재구성
- H2 찾는 쪽: 여러 번 다시 보는 게시물을 앞에 둘 방법이 없어 볼 때마다 훑어 찾거나 Saved 밖(DM · 캡처 · 메모)에 둔다. → 상단 고정 · 순서 변경

H1 · H2는 6주차 인터뷰로 확인한다([../WK06/form.md](../WK06/form.md)). 진입은 5주차 근거가 1명뿐이라 카드 소팅 · 트리 테스트로 근거를 만든다.

## 0. 가설 인터뷰 (6주차)

H1 · H2를 겪었는지, 그 이유가 무엇인지까지만 확인한다. 진입 근거를 보충하려면 "저장해 둔 걸 마지막으로 연 게 언제였는지, 어떻게 들어갔는지"(빈도 · 경로)를 함께 묻는다.

## 1. 휴리스틱 평가 — 지금 Saved 흐름 진단

닐슨 10원칙으로 저장 → 컬렉션 고르기 · 만들기 → 프로필 → 메뉴 → 저장됨 → 컬렉션 → 게시물 흐름을 평가한다. 나올 것으로 보이는 단점(예상):
- 유연성과 효율: 새 컬렉션은 저장 길게 누르기 → 새 컬렉션 → 이름 입력을 거친다 (H1)
- 시스템 상태의 가시성 · 기억보다 인지: 저장함이 메뉴 안에 있어 어디 있는지 기억해야 연다 (진입)
- 사용자 제어와 자유: 컬렉션 안에서 순서를 바꾸거나 고정할 수 없다 (H2)
- 기억보다 인지: 어디에 넣었는지 기억해야 하고, 저장 순서로만 쌓인다 (H2)
- 일관성: 프로필 게시물은 고정할 수 있는데 저장물은 못 한다 — 앱 안의 패턴을 Saved에서 못 쓴다 (프로필 고정 기능은 앱에서 확인 필요)

## 2. 카드 소팅 + 트리 테스트 — 인스타그램 정보구조에서 저장함의 자리 (진입)

개인 저장물로 하는 카드 소팅은 빼기로 했다. 사람마다 저장물이 달라 결과가 모이지 않고, 폴더를 만들고 저장하는 기능은 나누는 기준과 상관없이 같기 때문이다. 인스타그램 메뉴 · 기능은 모두에게 같아 디스코드 과제와 같은 조건이다.

**하이브리드 카드 소팅**
- 카테고리: 지금 앱의 최상위 구분(홈 · 검색 · 릴스 · 메시지 · 프로필 · 설정 및 활동 등)을 주고, 참가자가 새 카테고리를 만들 수도 있게 한다.
- 카드: 저장됨, 좋아요 누른 게시물, 보관, 하이라이트, 태그된 게시물, 친한 친구, 내 활동 등 20~30장. 지금 앱에서 실제 메뉴 이름 · 위치를 보고 만든다(자주 바뀜).
- 볼 것: '저장됨'을 지금 자리에 넣는 비율(낮으면 기대와 어긋남), 저장됨 · 좋아요 · 보관을 묶어 "내가 모은 것" 같은 새 묶음을 만드는지(새 상위 카테고리 근거 — 디스코드에서 즐겨찾기를 새 기능으로 제안한 것과 같은 논리).

**트리 테스트**
- 지금 구조를 글자로만 보여 주고 "저장한 게시물을 찾아가세요"라고 시킨다.
- 볼 것: 성공률, 첫 클릭, 거쳐 간 경로. "지금 구조에서 실제로 찾기 어렵다"를 수치로.

카드 소팅은 "어디에 있을 거라고 기대하는가", 트리 테스트는 "지금 구조에서 찾을 수 있는가"다. 둘을 같이 써서 "기대와 어긋나고, 실제로도 못 찾는다"는 근거를 만든다.

한계: 둘 다 "앞으로 꺼내야 한다"까지는 말해 주지 않는다. 하단 탭처럼 자리가 적은 곳에 올리려면 빈도 · 중요도 근거(0단계 인터뷰)가 더 필요하다. 인스타그램은 즉석 소비(체류 시간)에 무게를 두므로(5주차 인사이트), 저장함을 꺼내는 것이 회사에도 이득인지의 논리도 함께 준비한다.

## 3. 유저 테스트 — 태스크별 0~10점

쉬움 점수와 함께 시간 · 탭 수 · 막힌 지점을 적는다.

| 태스크 | 축 | 보는 것 |
|---|---|---|
| T1. 이 게시물을 새 컬렉션 '전시'를 만들어 저장하세요 | H1 | 단계 수, 새 컬렉션 버튼을 찾는지 |
| T2. 전체 저장에 있는 게시물 3개를 맞는 컬렉션으로 옮기세요 | H1 | 저장 뒤 정리 비용 |
| T3. 홈 화면에서 시작해, 저장해 둔 게시물 목록을 여세요 | 진입 | 시간, 탭 수, 첫 시도 위치 |
| T4. 몇 주 전에 저장한 ㅇㅇ 게시물을 찾으세요 | H2 | 시간, 훑은 컬렉션 수, 포기 여부 |
| T5. 가장 자주 보는 게시물을 맨 앞에 두세요 | H2 | 불가능 확인, 어떤 우회를 하는지(DM · 캡처) |

디스코드에서 점수가 낮은 곳(봇 1/10, 화면 공유 2.66/10)이 해결 우선순위가 됐듯이, 점수로 우선순위를 정한다.

## 4. 최종 인사이트와 해결 방향

- 카테고리 재구성(Saved I.A.): 저장함 진입 위치를 바꾼다(지금은 프로필 → 메뉴 안). 카드 소팅에서 새 묶음이 나오면 저장됨 · 좋아요 · 보관을 묶는 상위 카테고리. 컬렉션 안 고정 영역 · 사용자가 정하는 순서.
- 인터페이스 재구성: 저장 순간 "ㅇㅇㅇ 폴더를 생성할까요?" 같은 폴더 생성 · 추천 제안(디스코드의 팝업 툴팁과 같은 장치), 찾는 순간 길게 눌러 고정 · 끌어서 순서 변경(디스코드에서 즐겨찾기를 새 기능으로 제안한 것과 같은 방식).
- 폴더 이름까지 시스템이 제안한다면: 게시물 내용으로는 주제는 짐작해도 용도(레퍼런스 · 따라 하기)는 알 수 없다. 프로토타입에서 본인 저장물 10개에 제안한 이름을 받아들이는지 짧게 확인한다.

## 5. 기존 I.A. · 개선 I.A.

지금 Saved 구조(진입 경로 포함)와 개선 구조를 나란히 그린다.

## 6. 프로토타입과 재테스트 (디스코드 자료에 없던 단계)

개선안 프로토타입으로 같은 태스크 T1~T5와 트리 테스트를 다시 진행해 점수 · 성공률을 전후 비교한다. IPS는 반복이 목적이라 이 비교가 결론이 된다.

## 흐름

```
인터뷰(H1 · H2, 진입 빈도) → 휴리스틱 평가 → I.A. 카드 소팅 + 트리 테스트(진입)
→ 유저 테스트(T1~T5 점수) → 인사이트 → I.A. 재구성(저장함 꺼내기) + 저장 시 폴더 제안 · 고정 · 순서 변경
→ 프로토타입 → 같은 태스크 · 트리 테스트로 재테스트
```

한 사람에게 인터뷰 15분 + 카드 소팅 · 트리 테스트 10분 + 태스크 15분으로 한 번에 진행할 수 있다(모집 부담 줄이기). 카드 소팅 · 트리 테스트는 온라인 도구로 따로 더 많은 사람에게 돌릴 수도 있다.
