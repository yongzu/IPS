# 진행안 — 디스코드 인터페이스디자인 방법을 Saved에 적용

2026-11-10. 에이전트 제안(사용자가 저장 지시, 단계별 확정 전).

출발점: 사용자의 2024-2 인터페이스디자인 과제(디스코드 UX 분석). 그 흐름은
휴리스틱 평가(장단점) → 카드 소팅(클로즈드, 분류 기준이 직관적인지) → 유저 테스트(태스크별 0~10점, 막힌 지점) → 최종 인사이트 → 해결 방향(카테고리 재구성 + 인터페이스 재구성) → 기존 I.A. · 개선 I.A. → 시각화.

지금까지의 IPS는 인터뷰로 **왜** 그런지를 확인했다. 디스코드 방법은 **얼마나 · 어디서** 막히는지를 재고 해결안을 만든다. 둘을 이어 문제 확인부터 해결안까지 한 흐름으로 간다.

가설은 두 개다(사용자 결정, [../WK06/form.md](../WK06/form.md)).
- H1 저장 쪽: 맞는 컬렉션이 없을 때 새로 만드는 일이 번거로워 전체 저장이나 애매한 컬렉션에 넣는다.
- H2 찾는 쪽: 여러 번 다시 보는 게시물을 앞에 둘 방법이 없어 볼 때마다 훑어 찾거나 Saved 밖(DM · 캡처 · 메모)에 둔다.

## 0. 가설 인터뷰 (6주차)

H1 · H2를 겪었는지, 그 이유가 무엇인지까지만 확인한다.

## 1. 휴리스틱 평가 — 지금 Saved 흐름 진단

닐슨 10원칙으로 저장 → 컬렉션 고르기 · 만들기 → 프로필 → 메뉴 → 저장됨 → 컬렉션 → 게시물 흐름을 평가한다. 나올 것으로 보이는 단점(예상):
- 사용자 제어와 자유: 컬렉션 안에서 순서를 바꾸거나 고정할 수 없다 (H2)
- 기억보다 인지: 어디에 넣었는지 기억해야 하고, 저장 순서로만 쌓인다 (H2)
- 유연성과 효율: 새 컬렉션은 저장 길게 누르기 → 새 컬렉션 → 이름 입력을 거친다 (H1)
- 일관성: 프로필 게시물은 고정할 수 있는데 저장물은 못 한다 — 앱 안의 패턴을 Saved에서 못 쓴다 (프로필 고정 기능은 앱에서 확인 필요)

## 2. 카드 소팅 — 사람들이 실제로 무엇을 기준으로 나누는지

디스코드에서는 메뉴 분류를 봤지만, Saved에서는 분류 자체가 문제라 더 직접 맞는다.
- 방식: 오픈 카드 소팅. 디스코드는 클로즈드였지만, 이번에는 사용자가 스스로 어떤 기준(주제 · 용도 · 시기)으로 나누는지가 알고 싶은 것이다. 저장물 20~30개를 카드로 주고 직접 묶고 이름 붙이게 한다. 걸린 시간과 망설인 카드를 적는다(H1의 분류 비용).
- 추가 과제: "이 중 맨 앞에 두고 싶은 것 3개를 고르고 순서를 정해 주세요." (H2 — 고정 · 순서 변경 수요)
- 예상 인사이트: 디스코드의 "홈 안에 DM과 서버가 섞여 있다"처럼, Saved에서도 주제 기준(카페)과 용도 기준(레퍼런스 · 유즈풀)이 한 층에 섞여 있을 가능성. 이 결과가 "ㅇㅇㅇ 폴더를 생성할까요?"가 무엇을 기준으로 제안할지를 정한다.

## 3. 유저 테스트 — 태스크별 0~10점

쉬움 점수와 함께 시간 · 탭 수 · 막힌 지점을 적는다.

| 태스크 | 가설 | 보는 것 |
|---|---|---|
| T1. 이 게시물을 새 컬렉션 '전시'를 만들어 저장하세요 | H1 | 단계 수, 새 컬렉션 버튼을 찾는지 |
| T2. 전체 저장에 있는 게시물 3개를 맞는 컬렉션으로 옮기세요 | H1 | 저장 뒤 정리 비용 |
| T3. 몇 주 전에 저장한 ㅇㅇ 게시물을 찾으세요 | H2 | 시간, 훑은 컬렉션 수, 포기 여부 |
| T4. 가장 자주 보는 게시물을 맨 앞에 두세요 | H2 | 불가능 확인, 어떤 우회를 하는지(DM · 캡처) |

디스코드에서 점수가 낮은 곳(봇 1/10, 화면 공유 2.66/10)이 해결 우선순위가 됐듯이, 점수로 우선순위를 정한다.

## 4. 최종 인사이트와 해결 방향

- 카테고리 재구성(Saved I.A.): 저장함 진입 위치(지금은 프로필 → 메뉴 안), 컬렉션 안 고정 영역 · 사용자가 정하는 순서.
- 인터페이스 재구성: 저장 순간 "ㅇㅇㅇ 폴더를 생성할까요?" 같은 폴더 생성 · 추천 제안(디스코드의 팝업 툴팁과 같은 장치), 찾는 순간 길게 눌러 고정 · 끌어서 순서 변경(디스코드에서 즐겨찾기를 새 기능으로 제안한 것과 같은 방식).

## 5. 기존 I.A. · 개선 I.A.

지금 Saved 구조와 개선 구조를 나란히 그린다.

## 6. 프로토타입과 재테스트 (디스코드 자료에 없던 단계)

개선안 프로토타입으로 같은 태스크 T1~T4를 다시 진행해 점수를 전후 비교한다. IPS는 반복이 목적이라 이 비교가 결론이 된다.

## 흐름

```
인터뷰(H1 · H2 확인) → 휴리스틱 평가 → 오픈 카드 소팅 → 유저 테스트(T1~T4 점수)
→ 인사이트 → I.A. 재구성 + 저장 시 폴더 제안 · 고정 · 순서 변경 → 프로토타입 → 같은 태스크로 재테스트
```

한 사람에게 인터뷰 15분 + 카드 소팅 10분 + 태스크 15분으로 한 번에 진행할 수 있다(모집 부담 줄이기).
