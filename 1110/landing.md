# 랜딩 페이지 계획 — SO 기준으로

2026-11-10. 사용자가 준 랜딩 기준(SO1~SO4)에 맞춰 에이전트가 정리하고, 사용자가 고친 것을 반영했다.
사용자 결정: 대안과의 차별점(SO2), "사람들은 인스타그램 밖에 따로 저장한다" · "밖의 대안은 흐름을 끊는다" 섹션은 부합하지 않아 뺐다. 회사 입장에 대한 해결책을 넣고, 결과는 "사용자가 더 오래 머문다 → 회사의 이득"으로 쓴다.

문제 정의 · 회사 쪽 근거 · 올인원 논리는 [README.md](./README.md).

## 랜딩 기준 (사용자 제공)

- SO1: 제기한 문제를 장면 단위로 선명하게 제시한다 — 추상적 개념이 아니라 구체적 장면(언제, 어느 순간).
- SO2: 시장에 이미 있는 대안과의 차별점 · USP 한 줄. → 이번 프로젝트에서는 뺐다(사용자 결정).
- SO3: 스토리라인이 잘 읽히는 흐름 — 제목만 읽어도 읽힌다, 앞뒤 문장의 인과가 와닿는다, 읽는 동안 물음표가 떠오르지 않는다, 초반의 문제의식이 끝까지 이어지고 밸류 프로포지션이 명확하다.
- SO4: 문제의 심각성과 해결책의 가치가 드러나는 설득 — 가치를 더 매력적으로 보이게 하는 전략, 문제의식이 납득되는 주장.

## SO1 — 장면 세 개 (한 사람, 카페 게시물 하나를 끝까지 따라간다)

| 장면 | 언제 · 어느 순간 | 원인 |
|---|---|---|
| ① 저장 | 릴스를 보다 마음에 드는 카페 게시물을 저장하려는데 넣을 폴더가 없다. 일단 저장만 누른다. | 폴더를 새로 만드는 일이 번거롭다 (분류 비용) |
| ② 진입 | 주말에 그 카페에 가려고 저장함을 연다. 프로필 → 메뉴 → 저장됨까지 몇 단계를 거친다. | 저장함이 메뉴 깊은 곳에 있다 (진입 비용) |
| ③ 찾기 | 전체 저장과 '유즈풀' 폴더를 훑다가 포기한다. 자주 보는 것도 매번 처음부터 찾는다. | 저장 순서대로만 쌓이고, 앞에 둘 수 없다 (찾는 비용) |

같은 게시물이 장면을 이어 줘 SO3의 흐름도 같이 해결한다.

## SO3 — 스토리라인 (제목만)

1. 저장은 했는데, 다시 꺼내지 못한다
2. 저장하는 순간, 넣을 폴더가 없다
3. 저장함은 메뉴 안 깊은 곳에 있다
4. 들어가도, 자주 보는 것조차 매번 처음부터 찾는다
5. 인스타그램은 저장을 신호로만 쓰고, 돌아오는 길은 만들지 않았다
6. 저장할 때 돕고, 바로 들어가고, 앞에 꺼내 둔다
7. 다시 보는 순간이 새로운 탐색이 된다
8. 바뀐 결과: 사용자가 더 오래 머문다 → 회사의 이득
9. 보는 앱에서, 모으고 다시 쓰는 앱으로

점검: 제목만 읽혀도 이어지는가 · 앞뒤 인과 · 물음표가 없는가 · 1번의 문제의식이 9번까지 이어지는가.

## SO4 — 설득

- 심각성: 행동과 숫자로. 사용자의 말("그냥 폴더 하나 더 훑지 뭐"), 우회 행동(나에게 DM), 유저 테스트 점수 · 탭 수 · 시간, 트리 테스트 성공률.
- 가치: 프로토타입 재테스트의 전후 비교를 8번(클라이맥스)에 둔다.
- 회사 쪽: 저장은 이미 회사가 중요하게 보는 신호다(공식 자료). 다시 보는 순간을 새 탐색으로 이어 사용자가 더 오래 머물게 하는 것이 회사의 이득이라는 논리(5 · 7 · 8번).

## 한 줄 가치 제안 (초안)

> 저장한 순간부터 다시 쓰는 순간까지. 인스타그램 하나로 보고, 모으고, 다시 꺼낸다.

## 진행 순서

1. 지금 할 수 있는 것: 장면 3개 확정(SO1), 섹션 제목 9줄 다듬기(SO3)
2. 테스트: 인터뷰 · 카드 소팅 · 트리 테스트 · 유저 테스트로 숫자 확보(SO4 재료) — [process.md](./process.md)
3. 해결안: 프로토타입 → 재테스트로 전후 수치
4. 제작: 랜딩 페이지(저장소의 yongzu.github.io 스타일)

지금 가장 비어 있는 곳은 SO4다. 심각성 · 가치의 숫자는 테스트 뒤에 생긴다.
