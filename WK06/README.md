# IPS 6주차 — 가설 하나를 기준과 함께 다시 검증하기

과제 원문(사용자 제공, 2026-10-18). 이번 주차 작업은 이 폴더에서 한다.

- [제출폼 답변](./form.md) — 1~5번은 인터뷰 전에 채워 둔 답, 6~9번은 인터뷰 뒤에 채울 틀

검증할 가설은 2026-11-10에 다시 정의한 문제의 저장 쪽(분류는 필요하지만 새 컬렉션을 만드는 일이 번거롭다)에서 가져왔다 — [../1110/](../1110/README.md). 처음 가설(5주차 체인 A-2 → A-2-a, 찾은 뒤에도 옮기지 않는다)은 사용자가 폐기했다.

## 과제

1. 6주차 세션에서 얻은 원칙(최대 3개, 1문장씩)
   [cue]를 보면 [judgement]라는 판단을 하고 [strategy]를 사용한다.
2. 검증하고 싶은 가설
   [어떤 상황]에서 사용자는 [특정 경험]을 한 적이 있을 것이다.
3. 사용자 선정 기준
   포함 조건: 최근 [기간] 안에 [가설의 상황]을 직접 겪은 사람.
   배제 조건: [이유] 때문에 가설을 확인할 수 없는 사람은 제외한다.
   예) 포함 조건: 최근 [3개월] 안에 [전자제품 중고거래하는 상황]을 직접 겪은 사람.
   배제 조건: [전자제품이지만 금액이 3만원 미만의 저관여 제품이어서 제품을 충분히 볼 필요가 없기] 때문에 가설을 확인할 수 없는 사람은 제외한다.
4. 검증 기준
   - 지지 조건: 사용자가 [상황]을 겪었고, 그 때문에 [특정 경험]을 했다고 말하면 지지로 본다.
   - 반증 조건: 사용자가 [상황]을 겪었는데도 [특정 경험]을 하지 않았다면 지지되지 않은 것으로 본다.
   - 착시 조건: 사용자가 [특정 경험]을 했더라도, 그 이유가 [다른 이유]였다면 지지로 보지 않는다.
5. 질문 설계 및 시뮬레이션
   - 핵심 질문(최대 3개) → <질문 작성 시 유의사항> 참고
   - 각 질문마다 지지하는 답 · 반증하는 답: [사용자가 할 것 같은 말 abduction]
6. (인터뷰 후) 근거
   Q. [질문 원문] / A. [답변 원문] / 이 답은 [해석]을 보여준다. 따라서 [지지 / 반증 / 착시] 조건에 해당한다.
7. (인터뷰 후) 판정
   - 판정: [가설 검증 / 검증 안 됨 / 판단 불가]
   - 인터뷰한 [N]명 중 지지 조건 [n]명, 반증 조건 [n]명, 착시 조건 [n]명.
8. (인터뷰 후) 기준 수정 로그 및 다음 가설
   1) 질문 수정: 설계한 질문은 [5:질문]이었지만, 실제로는 [실제로 한 질문]이라고 물었다. 바꾼 이유는 [이유]다.
   2) 수정이 없다면: 수정 없음. 예상하지 못한 답은 [있었다면 그 답 / 없었다].
   3) 다음 가설: [어떤 상황]에서 사용자는 [특정 경험]을 한 적이 있을 것이다.
9. (인터뷰 후) 6주차 세션에서 얻은 원칙 적용 여부
   이번 과제에서는 지난 세션에서 배운 [cjs]를 적용했다. [사례 5줄 이내 기술]
