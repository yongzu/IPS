# 1117 — 진단에서 리디자인까지

2026-11-17. 1110에서 다시 세운 문제(저장 · 진입 · 찾기 세 축 + 회사 쪽, [../1110/README.md](../1110/README.md))를 디스코드 인터페이스디자인 방법([../1110/process.md](../1110/process.md))으로 풀어 간다.

## 진행 순서 (사용자 결정)

진단

1. 휴리스틱 평가 — 지금 Saved 흐름 진단 → [heuristic.md](./heuristic.md) (사용자 녹화 기준, 판정은 에이전트 초안)
2. 카드 소팅 — 인스타그램 인터페이스의 정보구조, 멘탈 모델
3. 유저 테스트 — 태스크마다 0~10점, Think Aloud 방식 차용
4. 최종 인사이트와 해결 방향 → [insight-solution.md](./insight-solution.md) (먼저 그려 본 초안 — 인사이트는 사용자 슬라이드 기준 저장 4 · 진입 3 · 찾기 4, 사용자 해결 메모를 SO1~SO3로 정돈)

해결

1. 실제 리디자인
2. 기존 I.A.와 개선 I.A.
3. 프로토타입과 재테스트
4. 최종 인사이트를 바탕으로 어떻게 해결되었는가
5. 랜딩 페이지 디자인

## 슬라이드 (피그마)

[Phi Design Institute 파일 · IPS_WK11 페이지 · 섹션 'IPS Saved 슬라이드 (2026-11-17)'](https://www.figma.com/design/dhXKmqQ2FMSZ3c0VEWETej/Phi-Design-Institute?node-id=2997-6325) — 템플릿 프레임 형식으로 15장(00 표지 ~ 14 다음 단계). 05 현재 IA 구조도, 13 개선 IA 포함. 글꼴은 Noto Sans KR로 들어가 있어 Pretendard로 바꿔야 한다(원격 편집 환경에 Pretendard가 없음).

## 1. 휴리스틱 평가 요약

사용자가 자기 계정으로 녹화한 Saved 사용 흐름(① 저장 → ② 새 컬렉션 → ③ 저장함 들어가기 → ④ 둘러보고 찾기 → ⑤ 순서 바꾸기 · 정리, 45초)을 단계마다 닐슨 10원칙에 대었다. 형식은 디자인DB(이모션글로벌) 글 — 계획 → 평가자 결정 → 실행 → 분석, 사용 흐름 단계별로 문제를 찾아 원칙으로 분석. 문제는 원칙 이름으로 적는다.

- 심각도 3: ⑤ 순서 변경 · 고정 없음 [유연하고 효율적인 사용], ① 어디에 넣을지 알려 주지 않음 [기억보단 인식], ③ 저장함이 설정 화면 안 [시스템과 현실의 일치성], ⑤ 옮기기 약 10탭 [사용자의 제어 및 자유].
- 문제는 흐름의 양 끝에 몰린다. 저장할 때는 어디에 들어갔는지는 알려 주지만(저장됨 · 보기 안내) 어디에 넣을지 판단을 돕지 않는다. 다시 꺼낼 때는 앞에 둘 수단이 없다. 그 사이는 설정 속에 있어 끊겨 있다.
- 녹화 · 캡처로 고친 것: 저장 버튼만 눌러도 컬렉션 창이 뜬다(도움말의 '길게 누르기'와 다름). 저장됨 안에 검색이 있다. 저장 뒤 '컬렉션이름에 저장됨 · 보기' 안내가 뜬다.
