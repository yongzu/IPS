# 유저 테스트 — 오픈 테스트 설계

2026-11-17. 진행 순서 진단 3단계. 가설은 [problem-hypothesis-insight.md](./problem-hypothesis-insight.md)의 네 축(저장 · 진입,탐색 · 제어 · 이어 보기)을 따른다. 피그마 섹션 'IPS Saved 유저 테스트 (2026-11-17)'(3035:6325)에 05 기획 · 06 진행 · 07 가설마다 보는 것 · 08 결과로 디벨롭하기 4장으로 넣었다. 테스트는 아직 하지 않았다.

**사용자 결정**
- 유저 테스트는 가설을 검증하는 방법이다. 철저히 객관적으로, 사람들이 문제 지점과 기능을 잘 활용하는지 본다. 테스트로 부족한 부분은 인터뷰로 채운다.
- 테스트 계정이 아니라 각자의 계정으로 한다(다양성, 각자 저장됨을 어떻게 쓰는지 보기 위해).
- 정해진 과제를 끼워 넣는 혼합안은 너무 복잡해 빼고, 오픈 테스트로 한다.
- 시작 전에 사용자의 응답을 먼저 듣는다 — 저장됨을 어떻게 쓰는지, 저장됨을 보지 않고 최근 저장한 것 중 기억나는 것이 있는지.
- 흐름: 릴스를 탐색해 20개쯤 저장(지시는 "나중에 찾기 쉽게 저장해 두세요" 수준까지, 새 컬렉션 · 설정 → 저장됨 같은 안내 없음) → 기억나는 릴스와 저장할 때의 사고 흐름 말하기 → (정리) → 저장한 것을 어떻게 활용할지 답하기.
- '정리' 단계는 컬렉션을 이미 나눠 둔 사람에게는 할 일이 없어 애매하다는 지적 → '바로 꺼내 보기'로 바꾼 안을 받아들임.
- 참가자는 사용자(디자인)와 같은 쪽에 몰리지 않게 다양하게. 단계마다 0~10점, Think Aloud.

**에이전트 제안(사용자 확인 전):** 사전 인터뷰 질문 문장, 사전 인터뷰 끝의 '기억난 것 열기'(진입,탐색 측정), '바로 꺼내 보기' 지시문과 조건부 옮기기, 마무리 질문 세 개와 그 위치, 가설마다 볼 것과 '문제로 보는 경우'(3명 이상), 디벨롭 문장.

## 기획

| | |
|---|---|
| 목적 | 네 가설이 실제로 일어나는지 본다. 사람들이 저장함의 기능을 어떻게 쓰고 어디서 막히는지 객관적으로 본다. 테스트로 못 보는 것은 인터뷰로 채운다. |
| 대상 | 5명 + 파일럿 1명. 디자인 관련은 최대 1명. 컬렉션을 나누는 사람과 안 나누는 사람, 나이, 주로 저장하는 것을 섞는다. |
| 방법 | 각자의 계정과 휴대폰. 화면 녹화, Think Aloud. 어디로 가라고 말하지 않고, 돕지 않는다. |
| 기록 | 단계마다 0~10점과 가장 헷갈린 곳. 길 · 시간 · 탭 · 한 말은 녹화를 보고 나중에 센다. 약 45분. |

본인 계정이라 다른 사람의 이름 · 게시물이 화면에 나온다. 녹화 동의를 받고, DM 화면은 녹화하지 않는다. 캡처를 쓸 때는 이름 · 얼굴을 가린다(1117 휴리스틱 캡처와 같은 방식).

## 진행

| 단계 | 시간 | 지시 |
|---|---|---|
| 0 사전 인터뷰 | 10분 | 저장됨을 열기 전에: "인스타그램은 주로 언제, 무엇을 보러 여세요?" / "어떤 걸 저장하세요? 저장하고 나면 보통 어떻게 되나요?" / "최근에 저장한 것 중에 기억나는 게 있나요? 어디에 넣었는지도요." / "저장해 둔 걸 마지막으로 다시 본 게 언제였어요? 어떻게 들어갔어요?" → 이어서 홈에서 시작: "아까 기억난다고 하신 걸 지금 열어 주세요." |
| 1 저장 | 15분 | "평소처럼 릴스를 넘겨 보다가, 나중에 다시 보고 싶은 걸 20개쯤 저장해 주세요. 나중에 찾기 쉽게 저장해 두세요." |
| 2 회상 | 5분 | "방금 저장한 것 중에 기억나는 걸 말해 주세요. 왜 저장했고, 무슨 생각을 했는지, 어디에 넣었는지도요." |
| 3 바로 꺼내 보기 | 10분 | "방금 저장한 것 중에 앞으로 자주 다시 볼 것 같은 걸 2~3개 골라 주세요. 다음에 열었을 때 바로 볼 수 있게 해 두세요." / 회상에서 다른 데 넣었다고 한 사람에게만: "아까 그거 원래 넣고 싶던 곳으로 옮겨 주세요." |
| 4 활용 | 5분 | "저장한 것 중 하나를 골라, 어떻게 써 볼지 말해 주세요. 지금 해 볼 수 있으면 해 봐도 돼요." |
| 5 마무리 질문 | 5분 | "오늘 저장한 방식이 평소랑 같았어요?" / "탐색 탭 오른쪽 위 저장 아이콘을 알고 있었어요? 써 본 적 있어요?" / "저장한 것 중에 여러 번 다시 열어 본 게 있나요? 저장 말고 다른 방법으로 남겨 둔 적은요?" / "저장해 둔 곳에 비슷한 게시물이 같이 보이면 어떨 것 같아요?" |

마무리 질문은 일부러 끝에 둔다. 앞에서 물으면 3 · 4단계 행동이 그쪽으로 기운다. 지시와 질문에는 가설 단어(분류 · 번거롭다 · 귀찮다 · 고정 · 순서 · 앞에 두다 · 숨어 있다)를 쓰지 않는다.

## UT 설계 양식 (피그마, x 430 · y 10286)

사용자가 붙여 둔 'UT 설계' 양식 사본에 넣은 판. 사용자 지시(2026-11-17): 태스크를 상자로 나누고, **확인할 점 = Yes/No로 행동으로 검증할 수 있는 것**, **체크포인트 = 내 가설이 맞는지 검증하기 위한 요소**(수업 피드백 메모)로 다시 정리. 태스크 · 확인할 점 · 체크포인트를 같은 줄에 맞췄다. 문장은 에이전트 정리.

사용자 지시로 태스크(무엇을 하게 하나)와 지시문(참가자에게 하는 말)을 다른 칸으로 나눴다.

| 태스크 | 지시문 | 확인할 점 (Yes / No) | 체크포인트 — 가설이 맞다면 |
|---|---|---|---|
| 0 사전 인터뷰 — 평소 저장 습관 듣기 | "어떤 걸 저장하세요? 최근에 저장한 것 중 기억나는 게 있나요? 어디에 넣었는지도요." | 저장됨을 보지 않고 최근 저장한 것과 넣은 곳을 말하는가? | 진입,탐색 — 넣은 곳을 기억하지 못한다 |
| 1 기억난 것 열기 — 홈에서 저장물 찾아가기 | "아까 기억난다고 하신 걸 지금 열어 주세요." | 탐색 탭 저장 아이콘으로 들어가는가? 3분 안에 그 게시물을 여는가? | 진입,탐색 — 아이콘 대신 프로필 → 설정 및 활동으로 가고, 첫 화면 그리드를 훑는다 |
| 2 저장 — 릴스 보며 20개 저장 | "릴스를 넘겨 보다가 다시 보고 싶은 걸 20개쯤, 나중에 찾기 쉽게 저장해 두세요." | 맞는 컬렉션이 없을 때 새 컬렉션을 만드는가? | 저장 — 저장됨에만 두거나 애매한 곳에 넣고, 저장 창에서 멈춘다 |
| 3 회상 — 저장한 것과 이유 말하기 | "방금 저장한 것 중 기억나는 걸, 왜 저장했고 어디에 넣었는지 말해 주세요." | 말한 넣은 곳이 실제 넣은 곳과 같은가? | 저장 — "맞는 게 없어서", "이름을 뭐로 하지" 같은 말이 나온다 |
| 4 바로 꺼내 보기 — 자주 볼 것 꺼내 두기 | "자주 다시 볼 것 같은 걸 2~3개 골라, 다음에 열었을 때 바로 볼 수 있게 해 두세요." | 꾹 누르기나 ⋯ 메뉴에서 고정 · 순서 바꾸기를 찾는가? | 제어 — 결국 캡처 · 나에게 DM · 새 컬렉션으로 우회한다 |
| 5 활용 — 저장한 것 하나 써 보기 | "하나를 골라 어떻게 써 볼지 말해 주세요. 해 볼 수 있으면 해 봐도 돼요." | 같은 주제를 더 보려고 저장한 릴스 밖으로 나가는가? | 이어 보기 — 구글 · 유튜브 · 지도로 나가며 "더 찾아보려고"라고 말한다 |

- 모든 단계에 Think Aloud를 요청한다.
- 가설 묶음: '테스트로 확인'(저장 · 진입,탐색) / '인터뷰로 함께 확인'(제어 · 이어 보기 — 반복 사용과 필요는 한 번의 테스트로 다 볼 수 없음).
- UT 후 질문: 오늘 저장한 방식이 평소와 같았나 · 탐색 탭 오른쪽 위 저장 아이콘을 알고 있었나, 써 본 적 있나 · 여러 번 다시 연 저장물, 저장 말고 다른 방법으로 남긴 적 · 비슷한 게시물이 섞이면 어떨지 · 단계마다 0~10점과 가장 헷갈린 곳.
- Participant 칸은 가설 칸 아래로 옮겼다(태스크와 확인할 점 · 체크포인트를 같은 줄에 맞추려고).

## 결과로 디벨롭하기

- **문제 정의:** 문제로 보는 경우를 넘은 축만 남기고, 가장 많이 막힌 순서로 다시 쓰기. 이어 보기에서 밖으로 나가는 행동이 보이면 개선 축으로 확정하고, 보이지 않으면 우선순위를 낮추기.
- **가설:** 테스트 결과와 인터뷰 답을 나란히 두고 검증, 약함, 검증 안 됨으로 판정하기. 맞은 가설은 참가자가 말한 이유로 원인과 대상을 더 좁히기.
- **인사이트:** 인사이트마다 확인, 약함, 기각, 새로 나옴을 붙이고 근거에 5명 중 몇 명인지 더하기. 내 녹화를 보고 쓴 문장을 참가자가 실제로 한 말로 바꾸기.

## 한계

- 20개를 한 번에 저장하는 것은 평소와 다르다. 마무리 질문 1번으로 평소와 같았는지 확인한다.
- 사람마다 저장물이 달라 개수는 더할 수 없다. 비율과 "5명 중 몇 명"으로 센다.
- 5명은 경향을 보는 수다. 비율을 일반화하지 않는다.
- Android의 저장함 경로가 녹화(iPhone)와 같은지는 확인 전이다. 파일럿 전에 본다.
- 재테스트는 프로토타입에 본인 계정 데이터를 넣을 수 없어, 프로토타입이 나올 때 방식을 다시 정한다.
