# 1123 — 핵심 문제를 '다시 찾기'로 좁히기

2026-11-23. 1117의 네 축(저장 · 진입,탐색 · 제어 · 이어 보기, [../1117/problem-hypothesis-insight.md](../1117/problem-hypothesis-insight.md))을 채팅으로 다시 정리했다. 핵심 문제를 하나로 세우고, 그 아래를 저장 · 탐색 · 관리 세 단계로 나눴다.

## 1117에서 바뀐 것 (사용자 결정)

- 핵심 문제는 **저장한 컨텐츠를 다시 찾기 어렵다**. 나머지 논점은 이것을 풀면 함께 풀리게 둔다.
- **이어 보기는 핵심 문제에서 뺀다.** 다시 찾기를 푼 뒤 더할 수 있는 플러스 알파다. UT에서는 과제로 시키지 않고 UT 후 질문 하나로만 묻는다.
- **진입은 뺀다.** 탐색 탭 오른쪽에서 저장됨으로 쉽게 들어갈 수 있다. 축 이름은 '진입,탐색'에서 '탐색'으로.
- **'제어'를 '관리'로 바꾼다.** 인스타그램이 '관리'라는 말을 쓴다.
- 저장하는 순간과 꺼내는 순간의 상황이 다르다는 설명은 뺀다. 사람마다 다르고 인스타그램이 바꿀 수 있는 부분이 아니다. 비용이 커서 편하게 쓸 수 없다는 점에 초점을 둔다.
- 저장 비용이 큰 이유는 탭 수보다 **릴스를 즐기는 흐름을 멈추고 컬렉션을 만들어야 하는 데** 있다.
- 저장 결과에서 '왜 저장했는지가 남지 않는다'는 뺀다. 왜까지 생각하지 않고 "나중에 봐야지" 하고 저장하는 경우가 많다.
- 탐색의 첫 화면은 큰 문제가 아니다. 최근 저장을 보여 주고 컬렉션 목록으로 들어갈 수 있다. 문제는 **컬렉션 목록** — 큰 커버 이미지만 있는 폴더가 한 화면에 6개만 보이는 레이아웃이다.
- 관리의 문제는 **저장물마다 가치를 매길 수 없다**는 점이다. 지금 관리에는 저장 취소(삭제)와 컬렉션(폴더)에 추가 두 기능만 있다. 저장순 · 시간순으로만 쌓여 값이 없으면 특정 컨텐츠를 다시 찾기 어렵다. 관리는 찾은 뒤에도, 다음에 찾기 전에도 작동한다(매긴 값이 접근을 쉽게 한다).
- 관리 해결은 사용자가 이미 익숙한 UX(아이폰 사진)를 빌리는 방안을 검토한다. 1117의 태그안(하트처럼 아이콘 태그, 태그별로 보기)과 이어진다.
- 저장할 때 즐겨찾기 같은 값까지 매기게 하는 안은 비용이 커질 수 있어 **보류**.
- "값을 매기면 다시 찾고 활용한다"는 **가설**로 가져간다. 한 번 찾고 다시 안 찾을 수도 있다. 확인되지 않더라도 사용자의 통제력을 올린다는 점에서 개선으로 본다.
- 필터(장편 영상 · 시리즈 · 오디오)는 사용자가 직접 써 보고 판단한다.

## 1. 핵심 문제

> 사용자는 컨텐츠를 나중에 다시 보려고 저장한다. 그런데 저장한 컨텐츠를 다시 찾기 어렵다.

저장할 때는 즐기던 흐름을 끊지 않으려고 전체나 애매한 컬렉션에 넣고, 찾을 때는 큰 커버 위주의 컬렉션 목록에서 원하는 폴더를 고르기 어렵고, 저장물이 저장순으로만 쌓이고 값을 매길 수 없어 특정 컨텐츠가 묻힌다.

다시 찾기를 쉽게 만들면 논점이 함께 풀린다(에이전트 정리).

| 풀면 | 풀리는 것 |
|---|---|
| 흐름을 끊지 않고도 맞는 곳에 넣게 한다 | 저장 비용 |
| 컬렉션을 한눈에 보고 고르게 한다 | 탐색 비용 |
| 저장물마다 값을 매기게 한다(순서 · 고정 · 즐겨찾기) | 사용자의 통제력, 다음 탐색의 지름길 |

## 2. 세 단계로 나눈 이유

다시 찾기 어려움은 찾는 순간에 드러나지만, 원인은 세 시점에 따로 있다. 하나만 고치면 나머지가 남는다.

| 단계 | 시점 | 다시 찾기 어려움과의 관계 |
|---|---|---|
| 저장 | 넣을 때 | 저장물이 전체나 애매한 컬렉션에 섞여, 컬렉션이 찾는 단서가 되지 못한다 |
| 탐색 | 찾을 때 | 컬렉션 목록이 한눈에 들어오지 않아 원하는 폴더까지 멀다 |
| 관리 | 찾은 뒤 값을 매기고, 다음에 찾을 때 그 값을 쓴다 | 값을 매길 수 없어 특정 컨텐츠가 묻히고 지름길이 생기지 않는다 |

탐색과 관리는 순환한다. 찾은 것에 값을 매기면, 그 값이 다음 탐색의 지름길이 된다(사용자 지적: 세 단계 전체가 아니라 탐색과 관리만 순환).

## 사용자 베네핏 (사용자 문장)

> 컨텐츠(릴스) 사용 흐름을 끊지 않으면서도, 저장을 적재적소에 쉽게 하며, 이를 큰 노력 없이도 다시 찾을 수 있다.

## 3. 단계별 문제와 원인

### 저장 — 넣을 때

- 문제: 맞는 컬렉션이 없으면 전체나 애매한 컬렉션에 넣거나 정리를 미룬다.
- 원인: 릴스를 즐기는 흐름을 멈추고, 새 컬렉션을 만들고, 이름까지 지어야 한다. 저장 창은 맞는 컬렉션을 추천하거나 이름을 제안하지 않는다(1117 휴리스틱 [기억보단 인식] 3).
- 결과: 저장물이 섞여, 컬렉션 이름만으로는 어디 있는지 알기 어렵다.
- 보류: 저장할 때 값까지 매기게 하는 안.

### 탐색 — 찾을 때

- 문제: 컬렉션 목록에서 원하는 폴더를 고르기 어렵다.
- 원인: 큰 커버 이미지만 있는 폴더가 한 화면에 6개만 보여, 컬렉션이 늘수록 계속 내려야 한다. 이름보다 커버가 앞서 이름으로 훑어 고르기 어렵다(1117 휴리스틱 ④ 큰 커버 [심미적이고 간결한 디자인] 2).
- 참고: 첫 화면은 큰 문제가 아니다. 필터는 직접 써 보고 판단한다.

### 관리 — 찾은 뒤, 그리고 다음에 찾기 전

- 문제: 저장물이 저장순 · 시간순으로만 쌓이고 저장물마다 값을 매길 수 없다. 값이 없으니 특정 컨텐츠를 다시 찾으려면 매번 목록을 훑어야 한다.
- 원인: 관리에는 저장 취소(삭제)와 컬렉션에 추가뿐이다. 순서 변경 · 고정 · 즐겨찾기가 없다(1117 휴리스틱 [유연하고 효율적인 사용] 3). 잘못 넣은 것을 옮기려면 여러 단계를 거친다(1117 기준 약 10탭).
- 결과: 중요한 것도 새 저장물에 밀려 묻히고, 캡처나 나에게 보내는 DM처럼 저장함 밖에서 값을 매긴다.
- 검토: 아이폰 사진의 하트(즐겨찾기 모음), 앨범 정렬(사용자 지정 순서 · 최신순 · 오래된순), 여러 개 선택. 익숙한 동작이라 새로 배울 비용이 적다는 것이 근거다. 어떤 동작을 빌릴지는 벤치마크로 정한다.
- 가설: 저장물마다 값을 매길 수 있으면, 사용자는 그것을 더 쉽게 다시 찾고 활용할 것이다.

## 4. 인사이트 (UT로 확인할 것, 문장은 에이전트 정리)

1. **흐름이 끊기는 저장** — 저장 비용의 핵심은 탭 수가 아니라 흐름이 끊기는 데 있다. 즐기던 흐름을 멈추기 싫어 대충 넣고, 컬렉션이 찾는 단서 역할을 못 하게 된다.
2. **한눈에 안 보이는 컬렉션** — 컬렉션 목록이 큰 커버 위주라 한 화면에 6개만 보인다. 컬렉션이 늘수록 원하는 폴더까지 멀어진다.
3. **같은 무게로 쌓이는 저장물** — 관리 기능이 삭제와 추가뿐이라 모든 저장물이 저장순으로 같은 무게로 쌓인다. 특정 컨텐츠가 묻히고, 사용자는 캡처나 DM처럼 저장함 밖에서 값을 매긴다.
4. **순환하는 탐색과 관리** — 관리에서 매긴 값이 다음 탐색의 지름길이 되어야 다시 찾기가 쉬워진다.

## 5. 가설 (저장 · 탐색 문장은 에이전트 정리)

| 단계 | 가설 | 확인 |
|---|---|---|
| 저장 | 나중에 다시 보려고 릴스를 저장할 때, 맞는 컬렉션이 없으면 즐기던 흐름을 끊고 새로 만들기 싫어 전체 저장이나 애매한 컬렉션에 넣은 적이 있을 것이다. | 테스트 |
| 탐색 | 저장한 게시물을 다시 찾을 때, 컬렉션 목록이 큰 커버 위주라 원하는 컬렉션을 바로 고르지 못하고 목록을 내리며 헤맨 적이 있을 것이다. | 테스트 |
| 관리 | 자주 다시 볼 게시물이 있어도 값을 매길 수 없어 매번 목록을 훑거나 저장함 밖에 따로 둔 적이 있을 것이다. 값을 매길 수 있으면 다시 찾고 활용할 것이다. | 테스트 + 인터뷰 |

## 6. 유저 테스트 과제 (UT 설계 고친 것, 에이전트 정리)

단계: 0 사전 인터뷰 · 기억난 것 찾아 열기 → 1 릴스 20개 저장 → 2 회상 → 3 자주 볼 것 표시하기. Think Aloud. '4 활용'은 뺐다.

| 단계 | 시키는 것 | 보는 것 | 문제로 보는 경우 | 인터뷰 |
|---|---|---|---|---|
| 저장 (1 · 2) | "평소처럼 릴스를 넘겨 보다가, 나중에 다시 보고 싶은 걸 20개쯤 저장해 주세요. 나중에 찾기 쉽게 저장해 두세요." / "방금 저장한 것 중 기억나는 걸, 왜 저장했고 어디에 넣었는지 말해 주세요." | 컬렉션에 넣은 수 · 새로 만든 수, 저장 창에 머문 시간, 맞는 곳이 없을 때 한 말과 행동 | 3명 이상이 그냥 두거나 아무 데나 넣는다 | "어떤 걸 저장하세요? 저장하고 나면 보통 어떻게 되나요?" "오늘 저장한 방식이 평소랑 같았어요?" |
| 탐색 (0) | "최근에 저장한 것 중 기억나는 게 있나요? 어디에 넣었는지도요." / 저장됨에서 "그걸 지금 찾아 열어 주세요." | 컬렉션 목록을 내린 횟수, 커버와 이름 중 무엇을 보고 고르는지, 게시물까지 걸린 시간과 헤맨 곳, 말한 곳과 실제 넣은 곳이 같은지 | 3명 이상이 컬렉션 목록에서 헤매거나 못 찾는다 | "저장해 둔 걸 마지막으로 다시 본 게 언제였어요? 어떻게 찾아 들어갔어요?" |
| 관리 (3) | "방금 저장한 것 중 자주 다시 볼 것 같은 걸 2~3개 골라, 다음에 열었을 때 바로 찾을 수 있게 해 주세요." | 고정 · 순서 변경 · 즐겨찾기를 찾는지, 결국 쓴 방법(새 컬렉션 · 캡처 · 나에게 DM · 포기)과 걸린 탭 수 | 3명 이상이 없는 기능을 찾거나 저장함 밖으로 우회한다 | "여러 번 다시 열어 본 게 있나요? 저장 말고 다른 방법으로 남겨 둔 적은요?" "자주 보는 것에 하트를 달 수 있다면 쓸 것 같아요?" |
| 이어 보기 (UT 후 질문) | 시키지 않음 | — | — | "(플러스 알파) 저장해 둔 곳에 비슷한 게시물이 같이 보이면 어떨 것 같아요?" |

확인할 점 6: 평소 저장함 사용 · 최근 저장 기억 / 기억난 저장물이 든 컬렉션을 목록에서 바로 고르는가 / 맞는 컬렉션이 없을 때 새로 만드는가 / 넣은 곳을 기억하는가 / 자주 볼 것에 값을 매기려 하는가, 밖으로 우회하는가 / 저장순 목록에서 특정 게시물을 훑어 찾는 데 얼마나 걸리는가.

check point 4: 컬렉션 목록을 내린 횟수 · 커버와 이름 중 무엇으로 고르는지 / 저장 창에 머문 시간 · '저장됨 · 보기'를 누르는지 / 고정 · 즐겨찾기를 찾는지, 캡처 · 나에게 DM으로 우회하는지 / 컬렉션 안에서 원하는 게시물까지 걸린 시간 · 내린 횟수.

UT 후 질문 6: 오늘 방식이 평소와 같았나 / 여러 번 다시 열어 본 게 있나 / 저장 말고 다른 방법으로 남긴 적 / 하트(즐겨찾기)를 달 수 있다면 쓸지 / (플러스 알파) 비슷한 게시물이 같이 보이면 / 단계마다 0~10점, 가장 헷갈린 곳.
